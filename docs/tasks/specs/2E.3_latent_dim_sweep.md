## Purpose

Retrain the `ConditionalSurfaceModel` at a deliberately chosen set of
`latent_dim` values (all other hparams fixed to the 2D.7 gaussian config),
re-run the 2E.2 diagnostic on each result, and produce a comparable
`val_nll` / `test_nll` / effective-rank table that supports a defensible
`latent_dim` recommendation for Phase 3.

This story exists **only as a follow-up to** [2E.2](2E.2_latent_capacity_diagnostic.md).
It must not be promoted to `todo` until 2E.2 is `done` and the addendum
in `docs/phase2_result_memo.md` has named the sweep direction
("shrink" / "expand" / "close-without-running") and the specific widths
to sweep.

The atomic-story rule applies: this story is one decision (pick a width
for Phase 3) backed by one artifact bundle (`sweep_summary.csv` + per-
width diagnostic bundles). It does **not** retread the 2E.2 diagnostic
on the existing checkpoint and it does **not** explore pooling /
calibration variants (those would be W7 / W8 stories).

## Why scope is deferred

Three scenarios are possible after 2E.2:

| 2E.2 finding | 2E.3 action |
|---|---|
| Effective rank ≪ 64 and top-k PCs recover val NLL for small k | **Shrink sweep.** Widths e.g. `{8, 16, 32, 64}` to confirm a smaller latent matches val NLL. |
| Effective rank ≈ 64, per-dim ablations roughly uniform, top-k recon curve flat | **Expand sweep.** Widths e.g. `{64, 96, 128, 192, 256}` to see whether more capacity actually helps. |
| Diagnostic confirms 64 is correct (small expand shows no gain, shrink shows clear loss in pilot) | **Close without running.** Mark this story `done` with a note; no training cost. |

Committing to a 6-width symmetric sweep before 2E.2 is in hand wastes
Pod budget. This story is therefore intentionally light on the widths
list — that field is filled in once 2E.2 produces its addendum.

## Non-goals

- Do NOT re-implement the diagnostic. Reuse the 2E.2 modules verbatim.
- Do NOT change `SetEncoder` pooling, decoder architecture, calibrator,
  or any hyperparameter other than `conditional.latent_dim`.
- Do NOT introduce a new dataset; reuse the AV benchmark
  `data_processed/spy/benchmarks/spy_phase1_random40_noiselow.parquet`
  identical to 2D.7.
- Do NOT re-fit the calibrator — sweep reports val/test NLL only.
- Do NOT commit per-width checkpoints (gitignored); commit only the
  per-width diagnostic summary CSVs and the aggregate `sweep_summary.csv`.

## Implementation steps

1. **Fill the sweep config.** Populate `configs/sweeps/latent_dim_sweep.yaml`
   from the 2E.2 addendum:
   ```yaml
   base_config: configs/conditional_2D7_gaussian.yaml
   sweep:
     conditional.latent_dim: [ ... fill from 2E.2 addendum ... ]
   seed: 42  # match 2D.7
   ```

2. **`scripts/run_latent_sweep.py`** — for each width:
   - Clone the base config dict in memory; override
     `conditional.latent_dim`; set `paths.checkpoint_dir`,
     `paths.log_dir`, `paths.results_dir` to
     `artifacts/diagnostics/2E3/sweep/latent_dim_<W>/...`.
   - Call `train_conditional(cfg)`.
   - Invoke the 2E.2 diagnostic pipeline against the resulting
     checkpoint (`run_latent_diagnostic.py` programmatic entrypoint or
     subprocess).
   - Append a row to `artifacts/diagnostics/2E3/sweep_summary.csv` with
     columns: `latent_dim, val_nll, test_nll, eff_rank_entropy,
     stable_rank, k95, k99, dead_pcs, top1_pc_variance_ratio,
     train_minutes`.
   - Redirect each width's training output to its own log file per
     `~/.claude/CLAUDE.md` §2.1.

3. **Wiring test (local).** Run `pytest tests/integration/
   test_latent_sweep_wiring.py -v -m integration` with `epochs: 1` and
   2 widths on synthetic data to validate the runner before launching
   the full sweep on the Pod.

4. **Pod smoke.** One width, `epochs: 2` override, end-to-end.

5. **Pod full sweep.** All widths from the populated config.

6. **Documentation update.** Append:
   - One `docs/experiments/experiment_journal.md` entry with the full
     `sweep_summary.csv` and a one-line recommendation.
   - A "Follow-up addendum: latent_dim sweep (2E.3)" section in
     `docs/phase2_result_memo.md` naming the chosen Phase 3 `latent_dim`
     and citing val/test NLL + effective-rank evidence.
