## Purpose

Phase-entry decomposition story for epic **3B — Cross-Attention
Decoder** under workstream **W11**. The architectural bet of Phase 3:
replace the global-pool → coordinate-decoder pipeline with a
query-attends-to-context decoder so each `(k, τ)` query attends over
encoded observations directly.

3B.1 selects one cross-attention architecture from the candidate set
in the Phase 3 roadmap (ANP, Set Transformer, TNP, Perceiver IO), with
cost / expected-value justification recorded in
**ADR 0005 — Cross-attention architecture choice**, then writes the
atomic stories that implement it on top of (or alongside) the existing
`SetEncoder` + `MultiOutputDecoder` from Phase 2.

## Implementation steps

1. Read every "Context files to read first" entry before writing.
2. Restate scope: 3B's deliverable is a single cross-attention variant,
   trained and evaluated end-to-end on AV, that either meets the Phase
   3 acceptance bar on its own or sets the stage for 3C to close the
   gap. **3B does not gate on 3A** — if 3A is `done` and Fourier won,
   3B inherits Fourier-encoded coordinates; if 3B starts before 3A
   finishes, default to Fourier-on as cheap insurance against
   coordinate-MLP spectral bias (per ADR 0004).
3. Write **ADR 0005** with the architecture pick, the per-query
   compute / latency expectation, and the explicit rejection rationale
   for the other candidates.
4. Set epic **3B** to `in_progress` on `BOARD.md`.
5. Draft the atomic 3B stories. Initial expectation (subject to your
   decomposition):
   - **3B.2** local: implementation of the cross-attention decoder
     module + unit tests + synthetic smoke + integration test against
     a tiny fixed-size synthetic dataset. No training run.
   - **3B.3** local: predictor-adapter wiring so the new architecture
     plugs into the existing W1 / W2 / W5 evaluator surface with the
     same artifact-shape parity (`pred`, `lower`, `upper`,
     `uncertainty`).
   - **3B.4** remote: full AV training with the new architecture under
     all three head kinds (`gaussian`, `quantile`, `point-control`).
   - **3B.5** remote: K-seed deep-ensemble training of the new
     architecture (parallels 2D.8).
   - **3B.6** local: calibrator re-fit (parallels 2D.4) on the new
     architecture's val predictions; commit calibrator + per-row
     metrics.
   - **3B.7** local: end-to-end decision-layer re-eval against all
     four Phase 2D baselines + the new variant; commit
     `results/3/<dataset>/<variant>/` bundle and journal entry.
6. For each new story, fully fill the upgraded `_template.md`.
7. Update Phase 3 roadmap § W11 with the concrete story list.
8. Update `docs/PHASE3_INDEX.md`.
9. Append `docs/logs/progress_log.md`.
10. Run PMR gate dry-run.
11. Mark `in_review`.
