## Purpose

Land a small, self-contained **coordinate-encoding module** and a single
constructor flag on the decoder that lets a downstream training run
choose between **raw `(k, τ)`** and **sinusoidal Fourier-encoded
`(k, τ)`** without touching any other part of the model. This is the
local pre-work for 3A.3's decoder-only remote retrain, and it carries
its own correctness signal (unit tests + a synthetic-data wiring smoke)
so a fresh session can land it without Pod access.

Local-only. No training. No checkpoint mutated. No new dataset.

## Scope contract (atomic story)

- **One question:** does the `coord_encoding={"kind": "fourier", ...}`
  path produce the right shapes and gradients on the existing
  `MultiOutputDecoder` while leaving `coord_encoding={"kind": "raw"}`

- **One artifact bundle:** the new `features/coord_encoding.py` module,

- **One acceptance check:** unit + integration tests green; existing

## Files likely to touch

### New

- `src/neural_iv_surface_inference/features/coord_encoding.py` —
  `RawCoordEncoding` and `FourierCoordEncoding` `nn.Module`s with a
  shared interface `forward(query: (B, N, coord_dim)) -> (B, N,
  encoded_dim)` and an `encoded_dim` property. A small builder
  `build_coord_encoding(cfg: dict, coord_dim: int)` constructs the
  right one from a config dict (`{"kind": "raw"}` or
  `{"kind": "fourier", "num_bands": int, "max_freq": float,
  "include_input": bool}`). Default frequencies follow Tancik et al.
  (NeurIPS 2020) log-spaced sinusoidal banding; concrete defaults
  chosen in this story and locked here (`num_bands=8`,
  `max_freq=10.0`, `include_input=True`).
- `tests/unit/test_coord_encoding.py` — `pytest.mark.unit`. Cases:
  - Output shape: `RawCoordEncoding(coord_dim=2)` returns
    `encoded_dim == 2` and passes input through.
  - Output shape: `FourierCoordEncoding(coord_dim=2, num_bands=8,
    include_input=True)` returns `encoded_dim == 2 + 2*2*8 == 34`.
  - Determinism: same input → same output across two calls (no
    stochastic state).
  - Gradient flow: backward produces finite gradients on the input.
  - Builder round-trip: `build_coord_encoding({"kind": "raw"}, 2)`
    and `build_coord_encoding({"kind": "fourier", ...}, 2)` return
    the expected types.
  - Unknown kind raises `ValueError`.
- `tests/integration/test_conditional_coord_encoding_wiring.py` —
  `pytest.mark.integration`. Cases:
  - Build a tiny `ConditionalSurfaceModel(..., coord_encoding=
    {"kind": "raw"})` and a tiny `ConditionalSurfaceModel(...,
    coord_encoding={"kind": "fourier", ...})`. Run a single forward
    pass on a synthetic batch. Assert output dict has the expected
    Gaussian keys (`mu`, `sigma`, `log_sigma2`) and shapes.
  - With `coord_encoding={"kind": "raw"}` and a fixed manual seed,
    output equals the current model's output on the same input (no
    regression on the default path).
  - With `coord_encoding={"kind": "fourier", ...}`, total parameter
    count differs from the raw variant by exactly the expected
    decoder trunk-input expansion (sanity check that the new flag
    actually routes through the decoder constructor).

## Non-goals

- Do NOT add SIREN, learned positional embeddings, or any non-Fourier
  encoding. The ablation in Phase 3A is binary (Fourier vs raw).
- Do NOT add RBF as a prior, residual base, or pretraining target.
- Do NOT modify the `SetEncoder` or any per-element / pooling code.
  3A is decoder-only.
- Do NOT touch `MultiOutputDecoder` head logic (Gaussian / quantile
  output channels stay exactly as is). The only change to the
  decoder is the `coord_dim` it sees.
- Do NOT train, evaluate against AV data, or produce result bundles.
  Those belong to 3A.3 (remote train) and 3A.4 (local eval).
- Do NOT add new YAML config files; the new flag is exercised via
  Python kwargs and tests. Wiring the flag through training config
  is part of 3A.3's scope.
- Do NOT exceed `file_scope`. If a real need arises (e.g., touching
  a predictor adapter), stop and split into a new backlog story.
