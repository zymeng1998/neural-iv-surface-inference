## Purpose

Wire the predictor interface (2A.2), core metrics (2A.3), and abstention curves
(2A.4) into one end-to-end runner that evaluates a predictor on a benchmark and
emits committed result artifacts. This is the integration story that makes W1
usable and satisfies roadmap §6.1 ("Interpolation, MLP ... all run through the
same uncertainty-evaluation interface and produce coverage, interval-width,
error-vs-uncertainty, abstention-curve, and high-confidence-MAE metrics") and
§6.7 (evidence discipline: result artifacts committed, run logged in the
experiment journal).

## Non-goals

- Do NOT run expensive training or large downloads. Use an existing local/CI
  fixture or a tiny synthetic benchmark; the smoke-test dataset is acceptable.
- Do NOT add real uncertainty signals (W4); since baseline `uncertainty=None`,
  interval/coverage metrics may be reported as NaN/skipped — document this and
  still produce the error-only + abstention-by-error portions that are defined.
- Do NOT modify `run_baseline.py`.

## Implementation steps

1. `report.py`: functions that take a `PredictionResult` + truth arrays and
   assemble a tidy metrics table (one row per predictor/split) plus a
   risk–coverage curve table.
2. `run_uncertainty_eval.py`: CLI (config + benchmark path + predictor choice)
   that loads splits, runs a predictor adapter, computes metrics + curve, writes
   `artifacts/results/uncertainty_eval_*.csv` and a risk–coverage figure.
3. Append an experiment-journal entry describing the run (dataset, predictor,
   headline numbers, artifact paths).
4. Test the runner end-to-end on a tiny fixture: artifacts created, CSV has the
   expected columns, curve table is well-formed.

## Rollback notes

source data mutated; benchmarks regenerate from the pipeline.
