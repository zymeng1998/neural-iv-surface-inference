## Purpose

Two local deliverables that the OTM audit gate (3X.5) needs:

1. **Vectorised audit v2** — `scripts/audit_duplicate_coordinates_v2.py`,
   same CLI + output contract as v1, but the per-group Python loop
   (`for key, idx in grouped.indices.items()`) is replaced with
   `groupby.agg([...])` + vectorised boolean ops. v1 spent 2 h 39 m on
   the strict file + one benchmark; v2 must make the **12-artifact**
   OTM audit (strict + 11 benchmarks) practical (D6, Q8).
2. **Paired-coordinate masking flag** — a `paired_coord: bool = False`
   option on the masking API so rows sharing a rounded
   `(date, log_m, tau)` key flip observed/held-out together (D4). Ships
   **off by default**; becomes mandatory only if the OTM audit gate
   (3X.5) finds residual leakage > 0.5 % per split.

## Implementation steps

1. Read the context files.
2. Write `audit_duplicate_coordinates_v2.py` reproducing v1's CLI,
   outputs (`duplicate_summary.csv`, `duplicate_iv_dispersion.csv`,
   `observed_hidden_leakage.csv`, `sparse_density_sensitivity.csv`,
   `headline.json`, markdown report), with vectorised aggregation.
3. Add `paired_coord` to `masking.py`: when `True`, build the rounded
   `(date, log_m, tau)` key, sample observed/held-out at the **key**
   level, broadcast back to rows. When `False`, the existing per-row
   path is untouched.
4. Write `tests/test_audit_v2_parity.py`: on the v1 fixtures, v2 matches
   v1 to ≤ 1 row count and ≤ 1e-9 on dispersion stats.
5. Write `tests/test_paired_masking.py`: synthetic fixture with a shared
   coordinate; assert `paired_coord=True` yields zero cross-key
   observed/held-out leakage and that `paired_coord=False` reproduces
   the current behaviour exactly (seeded).
6. Run tests; PMR gate dry-run; flip BOARD to `in_review`.
