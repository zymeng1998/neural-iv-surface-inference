## Purpose

Define the thin, model-agnostic predictor interface that the entire W1
uncertainty-evaluation layer (2A.3, 2A.4, 2A.5) and all future predictors
(interpolation, MLP, conditional neural models) plug into. Roadmap W1 calls for
"a thin model-agnostic predictor interface so interpolation, MLP, and future
neural models plug into the same evaluator." Without a stable contract for *what
a prediction carries*, the metrics modules cannot be written model-agnostically.
This story establishes that contract and retrofits the two Phase 1 baselines to
it.

## Non-goals

- Do NOT implement uncertainty metrics — that is 2A.3/2A.4.
- Do NOT invent real uncertainty signals for the baselines (ensemble,
  heteroscedastic, masking) — those belong to W4. Adapters return
  `uncertainty=None` for now.
- Do NOT modify the existing point-error `eval.py` behavior or `run_baseline.py`.
- Do NOT add new model architectures.

## Implementation steps

1. Create `eval/` subpackage. Define a frozen dataclass
   `PredictionResult` with fields: `pred: np.ndarray`, optional
   `uncertainty: np.ndarray | None`, optional `lower: np.ndarray | None`,
   `upper: np.ndarray | None`, and a `meta: dict` (model name, etc.). Validate
   array length consistency in `__post_init__`.
2. Define a `Predictor` `Protocol` with a method like
   `predict(df) -> PredictionResult`, where `df` carries the benchmark columns
   (`log_moneyness`, `tau`, `observed`, `iv_clean`, ...).
3. Write `InterpolationPredictor` and `MLPPredictor` adapters wrapping the
   existing `run_interpolation_baseline` and `predict_mlp`. Both return
   `uncertainty=None` (documented: real signals arrive in W4).
4. Unit-test: result construction/validation, length-mismatch rejection, both
   adapters return a `PredictionResult` of correct length with finite preds.
