## Purpose

Run audit v2 (from 3X.3) against the OTM strict surface + all 11 OTM
benchmarks (from 3X.4) to **prove the correction worked**. This is the
explicit human-review checkpoint in the split rental (Q4): if the OTM
audit passes, the CPU pod's work is done and a GPU pod can be rented; if
it fails, paired-coordinate masking (D4) or another correction becomes
mandatory before any OTM benchmark is used for claims.

## Where this runs

**Remote (RunPod), CPU pod** — same pod as 3X.4 (data is already there).
12 audit passes (1 strict + 11 benchmarks). Outputs pulled back and
committed (the per-cell CSVs are small).

## Scope contract (atomic story)

- **One question:** does the OTM substrate clear the ADR 0006 audit
  gate — contract-key dup ≤ 0.5 %, coord-key dup ≤ 0.5 % @ 10 dp, and
  exact-twin observed/held-out leakage ≤ 0.5 % per split — for the
  strict file and **every** one of the 11 benchmarks?
- **One artifact bundle:** `artifacts/audits/duplicate_coordinates_otm/`
  (per-artifact summary CSVs + a roll-up `otm_audit_gate.csv` with
  pass/fail per artifact) + `docs/research/duplicate_coordinate_audit_otm.md`.
- **One acceptance check:** the roll-up shows PASS for all 12 artifacts,
  OR a clearly-documented FAIL that routes to the D4 paired-masking
  remediation (which re-runs 3X.4 benchmark build with `paired_coord=True`
  and re-audits).

## Implementation steps

1. Read the context files; confirm 3X.3 + 3X.4 are `done`.
2. Run audit v2 on the OTM strict file → `..._otm/strict/`.
3. Loop audit v2 over all 11 OTM benchmarks → `..._otm/<variant>/`.
4. Build the roll-up `otm_audit_gate.csv`: one row per artifact with
   the three dup/leakage shares + a PASS/FAIL verdict against the 0.5 %
   thresholds.
5. Generate `docs/research/duplicate_coordinate_audit_otm.md` with the
   dirty-vs-OTM contrast headline (e.g. 93.61 % → expected ~0 %).
6. **If any artifact FAILS:** stop, document, and open the D4
   paired-masking remediation path (re-run 3X.4 build with
   `paired_coord=True`, re-audit). Do not proceed to GPU stories.
7. Pull back summaries; commit; journal + index + log.
8. PMR gate dry-run; flip BOARD to `in_review`; **request human review
   of the gate** before 3X.6/3X.7 proceed.
