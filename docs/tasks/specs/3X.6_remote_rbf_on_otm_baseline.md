## Purpose

Establish the **RBF floor** on the clean `random40_noiselow_otm`
benchmark *early* — before any GPU spend — as a sanity check that the
OTM benchmark construction produced a sensibly-difficult problem
(operator's "RBF-on-OTM early checkpoint" instruction). RBF is the
per-date interpolation baseline the whole Phase 3 bar is defined
against; knowing its OTM scale de-risks the GPU retraining that follows.

## Where this runs

**Remote (RunPod), CPU pod** — RBF is `scipy.interpolate`, no GPU
needed; runs on the same CPU pod as 3X.4 / 3X.5 right after the audit
gate passes. Outputs committed under `results/3/..._otm/rbf/`.

## Scope contract (atomic story)

- **One question:** what is RBF-on-OTM test/val MAE on
  `random40_noiselow_otm`, and how does it compare to RBF-on-dirty
  (0.0730 slice / 0.0662 full fold)?
- **One artifact bundle:** `artifacts/runs/3X6/rbf_otm/predictions_{val,test}.parquet`
  + `results/3/spy_phase1_random40_noiselow_otm/rbf/metrics_summary.csv`.
- **One acceptance check:** RBF-on-OTM produces finite predictions on
  every date; MAE is in a plausible range (flag if wildly off — that
  would indicate an OTM-build problem feeding back to 3X.4).
