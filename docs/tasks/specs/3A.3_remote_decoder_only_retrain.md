## Purpose

Run the **single controlled training experiment** that 3A exists to
answer: holding everything else equal versus the 2D.7 Gaussian
baseline, does **Fourier-encoded `(k, τ)`** close any of the gap to
RBF compared with **raw `(k, τ)`** when the encoder is frozen and
only the decoder is retrained?

This is the **remote-only** half of epic 3A. It depends on **3A.2**
landing the `coord_encoding` flag locally first.

## Scope contract (atomic story)

- **One question:** what are the val / test Gaussian NLL and test MAE
  of two decoder-only retrains (Fourier vs raw) on the
  `spy_phase1_random40_noiselow` AV benchmark, with the 2D.7 encoder
  frozen?
- **One artifact bundle:** `artifacts/runs/3A/{fourier,raw}/` — each
  with `manifest.json`, training curves CSV, and val/test predictions
  in the same shape as `artifacts/runs/2D7/gaussian/`. **No** evaluation
  bundles, **no** figures, **no** memo. Those are 3A.4.
- **One acceptance check:** both runs land their artifact bundles on
  disk with non-NaN training curves; manifests record that the
  encoder weights were loaded from the 2D.7 checkpoint and frozen
  during training.

## Dependencies

- 3A.2 `done`. The `coord_encoding` kwarg must exist on
  `ConditionalSurfaceModel`, with the `kind: raw` path bit-for-bit
  equivalent to the 2D.7 baseline.
- A reachable 2D.7 Gaussian checkpoint
  (`artifacts/runs/2D7/gaussian/checkpoints/...`) on the Pod.

## Files likely to touch

### New

- `configs/conditional_3A3_fourier.yaml` — clones
  `configs/conditional_2D7_gaussian.yaml`, sets:
  ```yaml
  conditional:
    coord_encoding:
      kind: fourier
      num_bands: 8
      max_freq: 10.0
      include_input: true
    freeze_encoder: true
    encoder_init_from: artifacts/runs/2D7/gaussian/checkpoints/<final>.pt
  paths:
    checkpoint_dir: artifacts/runs/3A/fourier/checkpoints
    log_dir:        artifacts/runs/3A/fourier/logs
    results_dir:    artifacts/runs/3A/fourier
  ```
  Seed, optimizer hparams, epochs, patience all identical to 2D.7.
- `configs/conditional_3A3_raw.yaml` — same as fourier but
  `coord_encoding.kind: raw`. Acts as the matched control (decoder-
  only retrain with the *raw* coordinate path, encoder frozen).
- `scripts/run_3a_decoder_only.py` — thin runner: load YAML, resolve
  paths, call `train_conditional(cfg)`. Mirrors `run_2d7_single.py`.
- `scripts/run_3a_decoder_only.sh` — Pod launcher: runs the fourier
  config and the raw config sequentially with output redirected to
  per-run log files per `~/.claude/CLAUDE.md` §2.1.
- `tests/integration/test_3a_decoder_only_wiring.py` —
  `pytest.mark.integration`. With `epochs: 1` on a synthetic dataset:
  - Confirms `freeze_encoder: true` actually freezes (encoder
    `param.requires_grad == False`; encoder weights unchanged after
    one step).
  - Confirms `encoder_init_from` loads encoder weights from a
    saved checkpoint into a fresh model.
  - Confirms the decoder *does* update.
  - Runs once with `coord_encoding.kind: raw` and once with
    `coord_encoding.kind: fourier`; both complete without error.

## Non-goals

- Do NOT unfreeze the encoder. 3A is decoder-only by construction.
- Do NOT introduce non-Fourier encodings (SIREN etc.).
- Do NOT use RBF as a prior, residual base, or pretraining target.
- Do NOT change `SetEncoder` architecture, decoder head, optimizer,
  schedule, loss, dataset, or seed.
- Do NOT produce a results bundle (figures, metrics CSVs) or memo
  — that is 3A.4's atomic responsibility.
- Do NOT touch any 3B / 3C / 3D file.
- Do NOT exceed `file_scope`. Predictor-adapter and evaluation work
  belongs to 3A.4.

## Compute requirements

This story has three compute phases. Plan the Pod rental around
phase (3); phases (1) and (2) are free.

| Phase | Locale | Hardware | VRAM | Wall time | Disk |
|---|---|---|---|---|---|
| (1) Configs + runner code + integration wiring test | local Mac | CPU-only | n/a | ~30 min dev + tests run in seconds on synthetic data | <100 KB |
| (2) Pod smoke (one variant, `epochs: 2`) | remote (RunPod) | single GPU — same tier as 2D.7 (typical: RTX 4090 / A40 / A100-40GB) | ~6–8 GB (matches 2D.7) | ~3–5 min wall | <50 MB |
| (3) Full Fourier + raw runs (50 epochs each, identical to 2D.7) | remote (RunPod) | single GPU — same tier as 2D.7 | ~6–8 GB | ~30 min wall **per variant**, run sequentially → **~60–75 min total Pod wall** | manifest + curves + predictions ≈ ~30 MB committed; checkpoints ~200 MB (gitignored) |

- **Recommended Pod rental window:** ~2 h to cover phase (2) smoke
  + phase (3) sequential runs + buffer for upload / log retrieval.
  Use the same Pod tier you used for 2D.7.
- **Sequential vs parallel:** the two variants are independent — if
  the operator wants to halve wall time and is willing to pay for
  two GPUs, they can be run on two Pods concurrently. Default is
  sequential on a single Pod (cheaper, simpler, ~60–75 min).
- **Notes:** no multi-GPU and no high-VRAM tier needed; this run is
  identical in size to 2D.7. The 2D.7 encoder checkpoint must already
  be reachable on the Pod (rsync from local or pull from object
  storage as part of the launcher script).
