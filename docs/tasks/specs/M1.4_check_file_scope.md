> `file_scope` is a hard contract — including for *this* story.

## Purpose

When a push touches one or more `docs/tasks/specs/*.md` story specs
that are `in_progress` or `in_review`, refuse the push if the diff
also touches any path outside the union of those specs' `file_scope:`
declarations.

This makes the `file_scope` declaration a real contract rather than
prose. It also handles the multi-story-per-push case: union of scopes.

## Scope contract (atomic story)

- **One question:** does the gate block out-of-scope edits when an
  active story's spec is in the diff, and allow them under explicit
  waiver only?
- **One artifact bundle:** gate script, pre-push wiring, tests.
- **One acceptance check:** synthetic test — push touches `M1.4` spec
  + a file not in its `file_scope` → blocked; same push with
  `WAIVE_SCOPE="reason"` → allowed + audit line.

## Dependencies

- M1.3 `done` (mirrors its UX + hook orchestration pattern).

## Context files to read first

- [`scripts/check_story_dependencies.py`](../../../scripts/check_story_dependencies.py)
  (mirror argparse / exit-code / audit-line conventions).

## Parsing contract

- `file_scope` is a YAML list of glob patterns under the spec's
  front-matter. Globs are matched with `fnmatch.fnmatch` (POSIX
  shell glob) on repo-relative paths.
- Active specs (those whose `status:` is `in_progress` or `in_review`)
  in the diff define the scope union for the push.
- If no active spec is in the diff, the gate is a no-op (passes).

## Waiver format

```
WAIVE_SCOPE="<reason>"
```

On waiver, append one audit line to each active spec's last checkpoint:

```
- SCOPE WAIVER (YYYY-MM-DDTHH:MM:SS-04:00): out-of-scope paths [path1, path2] → bypassed (reason)
```

## Non-goals

- Enforcing scope on `done` or `backlog` specs (immaterial).
- Auto-suggesting which spec a stray path "belongs to".
