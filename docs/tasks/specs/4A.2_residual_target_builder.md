## Purpose

Build the only genuinely new code surface in Phase 4: compute the per-date
RBF predictions at **query** coordinates and the additive residual target
`r = iv_true − rbf_pred` (ADR 0010), and expose a
`target_mode ∈ {absolute, residual}` flag on the conditional loader so the
existing trainer can fit `f_θ` on residuals with no other change. Ships the
builder + flag + tests **only** — the full dataset build is 4A.3, training
is 4A.4.

## Where this runs

**Local (Mac), CPU-only.** Smoke on a small date slice; no full build.

## Scope contract (atomic story)

- **One question:** can the loader yield residual targets (`iv − rbf_pred`)
  behind a flag, with the RBF-at-query computation matching the 3X.6 RBF
  baseline recipe, and `absolute` mode bit-identical to today?
- **One artifact bundle:** `residual_targets.py` (RBF-at-query + residual
  computation), `build_residual_targets.py` (driver), the `target_mode`
  flag, and tests.
- **One acceptance check:** `absolute` mode reproduces current loader output
  byte-for-byte; `residual` mode yields `iv − rbf_pred` with finite values
  on a smoke slice; RBF-at-query parity vs the 3X.6 baseline within tol.

   3X.6 recipe; add `residual_targets()`.

   IV target at query coords.
3. Driver `build_residual_targets.py` (writes residual parquet alongside the

   hand-checked tiny case, RBF-at-query parity vs baseline within tol.
