## Purpose

Remote counterpart to 3X.2. On the Pod, run `05_build_otm_surface.py`
to produce the single-valued OTM strict surface, then rebuild **all 11**
benchmark variants from it (D3), preserving every legacy artifact
byte-for-byte. CPU-only — this is the first half of the split rental
(Q4): build + audit gate run on a CPU pod, GPU is rented only after the
gate passes.

## Where this runs

**Remote (RunPod), CPU pod.** Reuses the existing Pod volume that holds
the dirty strict file + 11 dirty benchmarks (from 2C.7 / Phase 1). New
outputs:
`data_processed/spy/spy_surface_points_strict_otm.parquet` and
`data_processed/spy/benchmarks/spy_phase1_*_otm.parquet` (×11), all
gitignored. Manifests pulled back and committed under
`artifacts/runs/3X4/`.

## Scope contract (atomic story)

- **One question:** does the OTM builder produce a single-valued strict
  surface and 11 matched `_otm` benchmarks with sane row counts and the
  ATM-band sensitivity recorded?
- **One artifact bundle:** `artifacts/runs/3X4/` — `otm_build_manifest.json`,
  `benchmark_build_manifest.json` (per-variant row/split counts),
  `otm_residual_summary.json` (path + row count + rule counts + SHA-256
  of the residual CSV), ATM-band sensitivity table (inside the build
  manifest). The full `otm_residual_same_type.csv` is a **generated
  audit artifact** — retained on the Pod persistent volume and locally
  but **gitignored** (large, regenerable); its path, row count, rule
  counts, and hash live in `otm_residual_summary.json` /
  `otm_build_manifest.json`. Data parquets stay Pod-side (gitignored).
- **One acceptance check:** OTM strict file is single-valued at
  `(date, log_m, tau)` (verified by a quick Pod-side assertion); all 11
  `_otm` benchmarks build; legacy files untouched (hashes unchanged).

## Implementation steps

1. Read the context files; confirm 3X.2 is `done`.
2. Rent / attach a CPU pod with ≥ 25 GB free volume; pull latest code.
3. Hash the dirty strict file + 11 dirty benchmarks (record baseline
   hashes to prove non-mutation at the end).
4. Run `python src/data/05_build_otm_surface.py` (real). Inspect the
   manifest: row counts, per-rule drops, ATM-band sensitivity, residual
   fallback count. Apply the D5 escalation rule if needed.
5. Pod-side assertion: the OTM strict file has zero `(date, log_m, tau)`
   duplicates (quick `groupby().size().max() == 1` check, streamed).
6. Run `python src/data/04_build_benchmark_tasks.py --source strict_otm`
   (all 11 variants → `_otm` files).
7. Re-hash the dirty files; confirm unchanged.
8. Pull back manifests + residual CSV; commit under `artifacts/runs/3X4/`.
9. Update data lineage (OTM file canonical for 3X), journal, index, log.
10. **Verify persistent-storage visibility** of all OTM artifacts from a
    fresh shell; PMR gate dry-run; flip BOARD to `in_review`.
