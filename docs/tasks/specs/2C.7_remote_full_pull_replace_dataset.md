## Purpose

The remote-only execution counterpart of 2C.6. Pulls the **full** SPY option
chain history from Alpha Vantage `HISTORICAL_OPTIONS` (2008 → today) on the
RunPod remote, **deletes the prior Dubach-era data**, and rebuilds the full
data pipeline (02→03→04) so the project runs entirely on the new premium
dataset. This is the data-readiness gate for the conditional model's remote
training (2C.4 remote run) and the baseline rerun (2C.8).

Per the user's direction (2026-05-22): we are not maintaining two parallel
datasets — the Dubach snapshot is scratched, and the AV dataset becomes the
single source of truth.

## Implementation steps

1. **Sync the remote.**
   ```
   ssh <pod>
   cd /workspace/neural-iv-surface-inference   # or local equivalent path
   git fetch && git checkout <branch> && git pull
   export ALPHAVANTAGE_API_KEY="<paid-key>"    # session-scoped; not persisted
   df -h .                                     # confirm ≥80 GB free
   ```

2. **Scratch the old data** (per the dataset-replacement decision):
   ```
   rm -rf data_raw/spy/spy_options.parquet data_raw/spy/spy_underlying.parquet
   rm -rf data_processed/spy/partitions data_processed/spy/spy_surface_points*.parquet
   rm -rf data_processed/spy/benchmarks
   rm -f  data_raw/spy/ingest_metadata.json
   ```
   (Operator confirms once on the prompt; this is destructive on the remote.)

3. **Run the full AV ingest** (≈1.5–2 hours, rate-limited at 75 req/min):
   ```
   nohup python3 src/data/01_ingest_spy_alpha_vantage.py \
     --start 2008-01-02 --end "$(date +%F)" \
     > /tmp/av_ingest.log 2>&1 &
   tail -f /tmp/av_ingest.log     # then disconnect; check back later
   ```
   Verify on completion: `data_raw/spy/spy_options.parquet` exists, row count
   ≥ 25M, `ingest_metadata.json` `max_date` is within the last 3 trading days.

4. **Rebuild the surface tables and benchmarks** (output redirected per CLAUDE.md):
   ```
   python3 src/data/02_inspect_spy_schema.py     > /tmp/schema.log 2>&1; tail -20 /tmp/schema.log
   python3 src/data/03_build_spy_surface_table.py > /tmp/build.log  2>&1; tail -20 /tmp/build.log
   python3 src/data/04_build_benchmark_tasks.py  > /tmp/bench.log  2>&1; tail -20 /tmp/bench.log
   ```
   Confirm:
   - strict source row count (new dataset; will differ from the Dubach 21,386,789);
   - benchmark variants regenerated and consistent (per-file row count = strict source);
   - per-split counts (train/val/test) sum to total.

5. **Scratch old code** once the new path is end-to-end validated:
   `git rm src/data/01_ingest_spy_github_dataset.py` (the dead-source script).
   Commented dead-URL constants in `config.py` may stay as historical evidence
   or be removed at operator's discretion.

6. **Record** (PMR thoroughness):
   - `data_lineage.md` §3: replace the source table — Alpha Vantage is the
     active source; remove the Dubach line or move it to §9 as historical.
     Update §9 "Pipeline execution status" with the new strict row count and
     date range. Resolve the "Upstream data source unreachable" subsection
     (mark Resolved — replaced by AV).
   - `experiment_journal.md`: append a refresh entry — source, date range,
     contract count, strict row count, per-split counts, time to run.
   - `progress_log.md`: append completion entry.
   - Run `python3 scripts/pmr_prepush_gate.py --verbose --dry-run`.

## Rollback notes

This story is **destructive on the remote** (deletes the Dubach data). The
mitigation: do not run step 2 until step 3 has been smoke-validated against the
remote (a single-day AV pull on the Pod proves env + key + network), and the
operator has explicitly confirmed the destructive prompt. There is no remote
backup of the Dubach data after deletion — the source URL is dead, so a
re-fetch is impossible. If the new dataset proves bad, recovery means going
back to the Pod snapshot (if preserved elsewhere) or accepting the loss.
Code/doc changes are revertable via `git`.
